How to Use the Generative Design Setup

Welcome to the PCLS problem definition webapp. This tool allows you to visually construct regions, set analysis parameters, and export your problem space directly into a JSON schema ready for the custom topology optimiser.

1. Object Types & Roles

  • Preserve Regions (Green): Solid areas of material that MUST remain in the final design. These act as connection points where boundary conditions (loads and constraints) are applied.
  • Obstacle Regions (Red): Void areas (keep-outs) where material is strictly forbidden from growing during optimisation to avoid interference.
  • Primitives (Shapes): Base geometries (cuboids and cylinders) that build up the regions. Primitives themselves only represent mathematical bounding volumes; their combined CSG operation is what ultimately forms the solid region.

2. Operations & Hierarchy

  • Adding/Subtracting: Select a region, choose a shape (Cuboid/Cylinder) and an operation (+ Add or - Subtract), then click "+ Add Shape". Subtracting a primitive will carve out geometry from the collective region.
  • Grouping: Tick the checkboxes next to two or more independent regions and click "Link & Group". Grouping merges their physical identities, meaning boundary conditions applied to the group apply collectively to all regions within it simultaneously.
  • Duplicating (Dup): You can duplicate entire regions (spawning exact copies at identical physical spaces) or individual primitives (which applies a small physical offset for convenience).

3. Colors & Widgets Glossary

  • Green Translucent Volumes: Preserve (Solid) Regions.
  • Red Translucent Volumes: Obstacle (Void) Regions.
  • Orange Wireframes: Additive (+) Primitives.
  • Red Wireframes: Subtractive (-) Primitives.
  • Blue Highlights / Padlock Widget: Highlighted faces represent constrained areas. A padlock widget hovers in 3D space to indicate applied constraints. An opaque, locked padlock means Encastre (Tx, Ty and Tz all fixed). A slightly translucent, open padlock means only partial DOFs are fixed.
  • Orange Highlights / Arrow Widgets: Highlighted faces represent loaded areas. Straight red arrows represent Force vectors, pointing towards the geometric centroid. Curved purple arrows with a central axis line denote Moment loads.

4. Movement & Camera

  • Camera: Left-click and drag to rotate the view. Right-click and drag to pan. Scroll to zoom dynamically directly toward your mouse cursor.
  • Transform: Select a Region or Shape to reveal the movement gizmo. Use the toggle buttons (Move/Rotate/Scale) or enter specific values into the Properties panel on the left.
  • Resizing the Domain: Changing a Domain Dimensions field on the Domain tab genuinely rescales the whole problem to fit — every Region (Preserve and Obstacle alike), primitive and selected face pick is scaled proportionally, the same transform the Batch Edit "Rescale voxel grid" panel applies to a JSON file, just live. It is not a resize of the bounding box (that would leave existing geometry at its old absolute voxel coordinates, equivalent to only adding or removing voxels at the far edge). Edit two or three axes in quick succession (e.g. tabbing through X, Y, Z) and they are combined into one rescale rather than three sequential ones. A primitive rotated off a grid axis can only have its extent approximated under a non-uniform rescale (an exact solid box requires the same shear the schema can't represent) — you'll get a warning naming the affected Region so you can check it visually; a uniform rescale (all three axes by the same factor) is always exact regardless of rotation.

5. Boundary Conditions (Loads & Constraints)

  • Applying Constraints: Select a Preserve region or group. You can check Encastre Constraint to fix Tx, Ty and Tz automatically, or expand the DOFs ▾ dropdown to pick exactly which of the 3 translational degrees of freedom (Tx, Ty, Tz) to constrain. There is no rotational DOF to fix — the solver's elements have only translational degrees of freedom, so a region constrained in translation over more than one voxel already resists an applied moment through the couple formed by its distributed reactions. Choose to apply it to the bulk volume, or select specific faces by clicking them in the viewport (highlights blue).
  • Applying Loads: Click "+ Add Load" to add Force or Moment loads. Like constraints, choose whether the load applies to the bulk volume or specific faces (highlights orange).

6. Exporting & Batch Processing

  • Fill out the Analysis and Optimiser tabs according to your required simulation constraints.
  • Click Validate & Export JSON. The tool will rigorously validate your physics setup before allowing the `.json` file to export.
  • Batch Edit Directory: If you have multiple JSON problem files that need the exact same parameter changes (like identical timesteps), you can process a whole folder at once. Analysis Type is chosen from the same dropdown as the single-problem setup, so a batch edit can't write an unrecognised analysis type. The same modal can also rescale the voxel grid (e.g. convert a 40x10x10 problem to 80x20x30): the domain and every region, load and constraint are scaled to the new resolution together, so the physical layout is preserved.
  • Hyperparameter Sweep: Select multiple parameters and pass a comma-separated list of values to automatically generate every combination of problem setups into a folder alongside a reference key. Analysis Type sweeps over a checked subset of Conformal/Regular/Conjugate Gradient instead of free text, for the same reason.
  • Browser requirement: both of the above read and write whole directories using the File System Access API. That ships only in Chromium-based browsers (Chrome, Edge, Opera, Brave) and only over https:// or localhost. In Firefox or Safari the buttons still open, but they will explain the limitation rather than failing silently. Single-file export works everywhere.

7. Linear Buckling Constraint

  • What it does: enabling this on the Analysis tab adds a minimum buckling safety factor as a third constraint. Compliance-based optimisation happily produces long thin struts because they are stiff per unit mass; those struts can buckle at a fraction of their design load. This constraint steers the topology away from them. SIMP and the classical level set take it too; the level set can only move its boundary, so it cannot make holes for buckling.
  • Safety factor: the design requirement. A value of 2.5 means the structure must not buckle below 2.5× the applied load.
  • Ramping: set Initial SF below the target. Applying the full target the instant the constraint activates fights the volume constraint hard and can stall the topology before it has formed.
  • Mode count: use an even number. Buckling modes of symmetric structures come in degenerate pairs, and a mode set ending part-way through a pair has an ill-defined sensitivity.
  • Cost: a buckling evaluation is roughly 10–30× a plain compliance iteration. Use Evaluate Every and Activate After Outer to control this.
  • Important: linear buckling assumes a geometrically perfect structure and ignores imperfections and post-buckling behaviour. Thin-walled results — exactly what topology optimisation tends to produce — are imperfection-sensitive and can fail below the linear prediction. Treat the achieved factor as an optimistic upper bound and verify the final geometry with a nonlinear analysis.
